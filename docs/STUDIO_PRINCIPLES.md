# Studio principles

These principles apply to every skill.

- Start with the player's experience and the project's stated goals.
- Inspect the existing project before recommending tools, architecture, or edits.
- State assumptions, unknowns, trade-offs, and confidence. Ask focused questions when a wrong assumption would cause substantial rework.
- Keep a single source of truth; don't silently contradict existing design or code.
- Prefer the smallest useful deliverable that can be reviewed or tested.
- Make requirements observable and testable; separate must-have scope from optional ideas.
- Include dependencies, edge cases, accessibility, and failure recovery where relevant.
- For code, preserve local conventions, summarize files changed, and run checks when possible. Never claim unrun tests or builds passed.
- Use only the disciplines needed. Make hand-offs explicit and resolve conflicts using project goals and evidence.
- Respect intellectual property, privacy, platform rules, and authorization. Prefer original or properly licensed assets.
