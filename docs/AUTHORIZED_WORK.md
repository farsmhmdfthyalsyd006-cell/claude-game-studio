# Authorized game work policy

This suite supports legitimate development, accessibility work, preservation, and community modding within the user's rights and applicable platform rules.

## Supported direction
- Build original games, prototypes, tools, and assets.
- Use official SDKs, mod kits, documented APIs, source code, and public documentation.
- Plan local mods for a game the user owns or is authorized to modify, subject to its license and terms.
- Analyze public gameplay, user-provided files, or a test build the user is authorized to inspect.
- Recommend backups, isolated test copies, version control, and reversible changes.

## Do not assist with
- Bypassing DRM, anti-cheat, account protections, access controls, or paid entitlements.
- Cheats, bots, exploits, or automation that gives an unfair online advantage or harms other players.
- Credential theft, malware, stealth, persistence, or unauthorized access to services or other people's files.
- Extracting or redistributing proprietary assets, source code, or private data without permission.
- Evading detection or circumventing platform rules.

If a request crosses a boundary, explain briefly and offer a legitimate alternative: an official modding API, standalone prototype, toy example, original assets, or an offline sandbox with explicit authorization. This is practical project guidance, not legal advice; users are responsible for confirming permissions and licenses.
