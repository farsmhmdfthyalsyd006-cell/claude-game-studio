# QA Testing
1. Identify build/version, platforms, changed areas, dependencies, and known limitations.
2. Rank risks by player impact, likelihood, and detectability.
3. Define test cases with setup, steps, expected and actual results, and evidence.
4. Include save/load, pause/resume, input variations, accessibility settings, boundaries, and recovery where relevant.
5. Separate deterministic regression tests from exploratory testing and subjective playtest questions.
6. Use `templates/BUG_REPORT.md`; protect private data in captures and logs.
7. Summarize coverage, results, unresolved risks, and next recommended test.

Never invent results. Say clearly when a test is proposed but not executed.
