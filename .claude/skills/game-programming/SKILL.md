# Game Programming
1. Inspect repository structure, engine/version hints, relevant code, and tests before proposing edits.
2. Summarize current behavior and constraints. Ask before broad migrations or destructive changes.
3. Design the smallest change that meets acceptance criteria; account for lifecycle, input, save/load, state transitions, and errors as relevant.
4. Follow local style, abstractions, and asset/import conventions. Avoid needless dependencies.
5. Implement and add/update tests or manual verification steps.
6. Run available checks; report exact commands and outcomes and distinguish verified behavior from assumptions.
7. Summarize files changed, limitations, and follow-up work.

Never claim an unrun build or playtest passed. For mods, follow `docs/AUTHORIZED_WORK.md`; don't bypass protections or enable unfair online play.
