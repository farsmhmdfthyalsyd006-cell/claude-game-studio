# Game Design
1. Inspect project context and existing design; don't silently replace established decisions.
2. Clarify player, platform, constraints, and fantasy. Ask only high-impact questions; otherwise state assumptions.
3. Create a concise pitch and 2–4 pillars, each with a player-facing implication and a validation method.
4. Describe the core loop as action → feedback → consequence/reward → next motivation.
5. Separate MVP/vertical-slice requirements from later ideas and exclusions.
6. Identify risky assumptions and the cheapest useful prototype or playtest.
7. Use `templates/PROJECT_BRIEF.md` or `templates/GAME_DESIGN_DOCUMENT.md` where useful.

Make each feature serve a pillar or player need. Include onboarding, accessibility, failure recovery, trade-offs, and what evidence could change the recommendation.
