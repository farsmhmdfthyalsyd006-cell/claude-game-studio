# Systems Design
1. Review project pillars and nearby feature specs.
2. Define the player goal, actions, system states, transitions, feedback, costs, and rewards.
3. Map edge cases: invalid input, failure, pause/resume, save/load, and recovery where applicable.
4. Identify system interactions and degenerate strategies in the design.
5. Write observable acceptance criteria and initial tuning ranges; distinguish hypotheses from facts.
6. Recommend a cheap prototype and test for the riskiest assumption.
7. Use `templates/FEATURE_SPEC.md` for hand-offs.

Include the player-facing purpose, accessibility, dependencies, open questions, and must-have/later scope.
